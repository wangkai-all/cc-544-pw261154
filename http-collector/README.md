# HTTP 数据采集站（Vary 感知缓存 · ETag 条件请求 · 代次控制）

一个零第三方依赖的 Node.js 教学项目，包含一个**可控源站**和一个**采集站**，用于演示
HTTP 缓存中 `Vary`、`ETag`、条件请求与“本地发起代次”协作的正确语义。

## 运行

```bash
npm start                 # 同时启动源站(:5000)与采集站(:4000)
# 浏览器打开 http://127.0.0.1:4000
```

也可分别启动：

```bash
npm run origin            # 仅源站，:5000
npm run collector         # 仅采集站，:4000
ORIGIN_PORT / COLLECTOR_PORT / ORIGIN_URL / COLLECTOR_URL 可覆盖端口与地址
```

端到端核对（自动起两个服务、真实 HTTP 访问、用源站访问记录核对）：

```bash
npm test                  # 22 个断言，覆盖全部要求场景
```

## 目录

```
src/origin.js      可控源站：同 URL 按 Accept-Language / Accept 返回不同表示
src/collector.js   采集站：Vary 键、ETag 条件请求、代次闸门、采集流水
src/start-all.js   同时拉起两个服务
lib/util.js        头大小写、Vary/max-age 解析、缓存键构造
public/            控制台页面（编辑请求头、采集、看正文/命中理由/上游请求/源站控制）
test/smoke.mjs     端到端核对
```

## 核心语义与实现位置

### 1. 缓存键不是 URL，而是 URL + Vary 指定头的取值

`lib/util.js#buildCacheKey`：键为 `URL::<头名>=<值>|...`，头名统一小写（大小写不敏感），
**头缺失**写成 `__ABSENT__`，与“头存在但空值”严格区分。源站对同地址 `/data`
按 `Accept-Language`（zh/en）与 `Accept`（json/text）返回 4 份不同表示，各自独立保存
**正文、ETag、来源请求头、有效期（max-age 到期时间）**。

### 2. 条件请求与 304（`collector.js#fetchAndPublish`）

- 新鲜命中：不发上游请求，直接返回本地表示并记录命中理由。
- 过期但有正文 + ETag：带 `If-None-Match` 发条件请求。
- 收到 **304 只能沿用本次校验的那一份正文**（同缓存键、同一条目），仅刷新有效期/ETag。
- 本地正文缺失时不发条件请求、直接无条件获取；任何路径都**不返回空内容、不借用别的语言/类型的正文**。
- 304 不携带新表示，因此不参与 Vary 变化检测，键与维度沿用本地条目。

### 3. Vary: * 不进缓存

识别到 `Vary: *` 的响应 `cached=false`，每次都回源；真实请求/响应仍记录在流水里。
本项目只处理 GET、ETag、Vary 与明确的 `max-age`，未实现浏览器完整缓存协议。

### 4. 规则切换与代次（只表达本地发起先后，不判断业务新旧）

两级代次，全部基于**本地发起时刻**：

- **epoch（代次）**
  - 源站切换规则并 webhook 通知 → 所有已知 URL 的 epoch +1，旧键立即失效（`bumpAllEpochs`）。
  - 无通知时，采集端从**新的上游响应**识别到 Vary 集合变化 → 仅该 URL 的 epoch +1（`vary-detected`）。
    没有通知也没有新响应时，不会凭空发现源站变化。
  - 切换前已在途的请求返回时 epoch 对不上，**拒绝写回缓存**（真实响应仍返回、仍留痕）。
- **seq（同键发起序号）**
  - 同一缓存键按本地发起顺序递增；仅当“更早序号晚于更晚序号被确认”时拒绝覆盖，
    保证晚返回的旧响应不能覆盖后来已确认的结果；不同语言/类型是不同键，各自保存互不影响。

通知只表示“规则可能变了”，不携带业务内容；代次不宣称能判断源站正文的业务新旧。

### 5. 可控源站能力（`/admin/*`）

- `PUT /admin/body`：编辑某条表示正文，ETag 版本 +1（旧 ETag 立即失效），不主动通知。
- `POST /admin/switch-rule`：切换规则集 A/B/C（Vary 字段集合变化，C 为 `Vary: *`），
  可带 `silent:true` 不发通知，用于验证响应侧识别。
- `POST /admin/delay`：给匹配语言/类型的下一个请求加延迟，制造“旧请求晚返回”。
- `GET /admin/state`、`/admin/requests`：真实入站请求记录（含实际请求头、状态、延迟、规则集）。

## 页面可完成的操作

页面顶部“一键演示场景”覆盖：首次接收、条件校验（304 与 ETag 变更后的 200）、切换语言、
删除本地正文再取回、旧请求晚返回、通知切换、静默切换、`Vary: *`。
页面下方可手动增删请求头（删除行=头缺失，空值=存在但空）、强制采集、删除缓存条目/仅删正文，
并实时展示缓存表示、采集流水（命中理由 + 真实上游请求/响应）、源站真实访问记录与代次事件。

## 端到端核对要点（`npm test`）

- 同地址 zh/en、json/plain 产生不同缓存键与不同正文，核对源站记录确认无串用、命中不发请求。
- 过期条件请求得到 304 且沿用本地正文；改正文后 ETag 变化，条件请求得到 200 新正文。
- 删正文后无条件重取，源站记录确认未携带别的表示的 `If-None-Match`。
- 延迟制造并发：后发请求先确认，晚到旧响应被拒写回，另一语言表示不受影响。
- 通知/静默两种切换：旧键失效、在途请求拒写、`vary-detected` 事件与代次递增符合预期。
- 头缺失 vs 空值产生不同键；头名称大小写不敏感命中同键；`Vary: *` 每次回源。
